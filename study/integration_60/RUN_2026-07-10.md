## What was executed

For each article, the batch runner:

1. loaded the committed source manifest and verified its own SHA-256 commitment;
2. enforced the frozen 30 development / 10 validation / 20 locked-test ordering;
3. downloaded the current Europe PMC JATS XML;
4. required the XML SHA-256 to match the snapshot used during the original screening run;
5. extracted exact-span literature facts and phase-aware MD protocol events;
6. validated explicit PDB identifiers through the live PDBe API;
7. discovered UniProt accessions from PDBe mapping responses rather than guessing them;
8. validated each returned UniProt accession;
9. preserved SIFTS-derived PDB-chain to UniProt residue ranges;
10. wrote a compact integrated JSON record and a transactional SQLite record.

All 60 JATS source hashes matched the frozen manifest. Therefore, this run did not silently substitute newer article content for the screened snapshots.

## Golden-case gate

Before the 60-article batch, the Woo et al. 2020 golden case passed against live services:

- literature identifiers: `6VSB`, `6VXX`;
- live PDBe validation: both entries validated;
- mapping discovery: both structures mapped to UniProt `P0DTC2`;
- live UniProt validation: `P0DTC2` validated;
- residue scope: PDB → UniProt only;
- MD → PDB scope: `not_computable`, because no prepared topology, trajectory, or explicit residue-correspondence file was supplied.

This is the intended scientific boundary. SIFTS cannot prove how a prepared MD system was renumbered.

## Failure found by the first batch and corrective action

The first full run completed 59 articles and rejected `PMC7219429`. The extractor recovered an explicit temperature of `0 K`, but the schema required `temperature_k > 0`.

That was a schema error, not a bad article and not a service failure. Molecular-simulation methods may explicitly describe a nominal 0 K starting or cooling state. The constraint was changed to:

```python
temperature_k: float | None = Field(default=None, ge=0)
```

A regression test now requires 0 K to be preserved, while negative Kelvin remains invalid. The correction was merged as commit `89706ec6e7cc8e360a96bd4ca0ed1e3070355ade`, after Python 3.11, Python 3.12, full coverage, integration, and live golden-case checks passed.

The corrected batch then completed 60/60 articles with zero failure.

## Interpretation

These results establish **integration coverage and executable software behaviour**, not metadata-extraction accuracy.

The run demonstrates that the pipeline can:

- preserve article evidence separately from database enrichment;
- validate real structure and sequence identifiers;
- record residue-level PDB–UniProt mappings;
- distinguish `validated`, `conflict`, `unresolved`, and `not_applicable` states;
- continue through articles that do not state a PDB identifier;
- reject source drift through JATS hash checks;
- store searchable integrated records without embedding full article text;
- state that MD files are absent rather than inventing file provenance or MD-residue mappings.

The 423 protocol events are machine-generated candidates. They are not a human gold standard, and they should not be compared directly with the earlier 281 frozen predictions because the two runs use different paragraph-selection scopes.

## Important limitation exposed by the run

None of the 60 literature records supplied prepared coordinates, topology, trajectory, or an explicit MD-to-PDB residue correspondence through this workflow. Consequently:

```text
PDB residue → UniProt residue       supported by PDBe/SIFTS
MD topology residue → PDB residue   not established
```

A future file-backed benchmark must use public MDDB/MDposit projects with downloadable topology and trajectory assets. That benchmark should add:

- file-format validation;
- atom and residue counts;
- topology–trajectory consistency;
- software/version/input-command provenance;
- prepared-structure → starting-PDB alignment;
- composed MD → PDB → UniProt residue mapping.
