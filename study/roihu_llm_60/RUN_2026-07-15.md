## Reproducibility boundary

The repeated prompt inside each run was identical at temperature zero. Separate Slurm runs were
not bitwise deterministic:

- one of 7 one-to-five overlapping task response hashes differed, with no classification or event
  count difference;
- three of 64 five-to-sixty overlapping response hashes differed;
- all 64 repeated classifications were unchanged; and
- one repeated task retained one additional evidence-valid event in the 60-article run.

Two of the three five-to-sixty raw-response differences normalized to the same accepted or rejected
scientific result. The third changed the normalized event count from two to three. The report does
not hide this boundary: fixed seed and temperature zero are insufficient evidence of cross-job
bitwise reproducibility on this GPU stack. Production comparisons should use task-level normalized
commitments and explicitly quantify cross-run disagreement.

## Preserved remediation lineage

Failed runs were retained rather than overwritten:

- 187227, 187984 and 188199 documented the transition from zero accepted events to stricter
  evidence auditing and a corrected prompt;
- 188846 showed that one unclean completion could abort a whole batch after 64 classified tasks;
- 189276 classified all 740 tasks but correctly failed because 9 generation rejections exceeded
  the predeclared allowance of 7; and
- 189318 exposed a prompt-side numeric-cap cue that encouraged a task to fill the cap and left the
  one-article gate with zero accepted events.

The accepted implementation isolates per-task generation failures, preserves raw private response
commitments, constrains candidate-array growth in the schema, and avoids putting the cap number in
the model prompt.
