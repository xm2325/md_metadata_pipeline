# Scale80 PDBe-KB enrichment and SQLite v1 to v2 migration drill

## Result

On 2026-07-16, the direct PDBe-KB adapter processed all 107 distinct UniProt accessions from the
completed 80-article scale integration. The accepted recovery run produced 94 validated accession
records, three explicit `not_applicable` records and ten unresolved records. It compacted 815
annotation groups, 152,861 residue ranges, 390 annotation-partner links and 2,732 distinct linked
PDB identifiers without retaining full protein sequences or raw API payloads in the report.

This is integration, upstream-coverage and operational evidence. It is not an accuracy result and
used no human reference labels. The ten unresolved records remain explicit: the endpoint outcomes
were four non-JSON HTTP 502 annotation responses plus read timeouts affecting five annotation and
five partner requests, with overlap at accession level. They were not converted into biological
absence. Eight annotation 404 responses and three partner 404 responses were represented as
explicit no-data states; accessions with both endpoints at 404 became `not_applicable`.

## Database and API drill

The exact schema-v1 scale database (`e2f348…`) was copied into a private CSC scratch run. A first
ordering probe proved that the version-0.12 runner fails closed when pointed directly at schema v1.
The accepted sequence then:

1. created an online v1 backup and migrated a separate copy transactionally to schema v2;
2. recorded the migration SQL hash, source database hash and backup hash;
3. ran PDBe-KB enrichment against the v2 snapshot with four bounded workers;
4. imported the content-committed compact report into the v2 PDBe-KB tables;
5. checkpointed and verified all 80 stored article records, SQLite integrity and foreign keys; and
6. queried the new endpoint under production read-only settings.

The final database had SHA-256 `c5a71de8…`, schema version 2, 80/80 valid record JSON documents,
zero foreign-key violations and no SQLite sidecars. `/pdbekb/A0A0H3JX61` returned one validated
record with HTTP 200; a missing accession returned HTTP 404. The complete machine-readable counts
and hashes are in [run_summary.json](run_summary.json).

## External resource contract

The adapter uses the public PDBe-KB graph API endpoints for UniProt annotations and annotation
partners. PDBe-KB describes its annotations as an integrated Neo4j knowledge graph exposed through
REST services, and publishes the data under CC BY 4.0. See the official
[PDBe-KB services](https://www.ebi.ac.uk/pdbe/pdbe-kb/services),
[graph schema](https://www.ebi.ac.uk/pdbe/pdbe-kb/schema) and
[PDBe-KB overview](https://www.ebi.ac.uk/pdbe/pdbe-kb).

## Reproducibility and retention boundary

The full compact report is 815,600 bytes, has content commitment `329a30c8…` and file SHA-256
`b5768b06…`. It remains in the authorised private CSC run directory and is not committed because
the public repository retains the smaller audit summary. Raw cache responses are operational
cache data, not release artifacts. A governed release still requires an authorised dataset
identifier, licence decision for this project, creators, publisher and durable repository.
