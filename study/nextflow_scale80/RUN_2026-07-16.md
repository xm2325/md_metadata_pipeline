## Corrective evidence

Two bounded first-process probes failed before Python opened the database:

1. job 194542 inherited the ARM `python-data` module from the GPU login node into an x86_64
   `small` task; and
2. job 194727 showed that sourcing CSC initialization in a non-login task did not reset the
   inherited module path.

Both exited 255 at the container architecture check. The durable fix clears inherited modules,
adds CSC's x86_64 AIDA module path explicitly, loads `python-data/3.12-31.03` inside each task and
asserts `uname -m=x86_64`. Job 195246 then passed the same first process, followed by all remaining
processes. The failed run directories and logs were retained; no data mutation or result promotion
occurred.
